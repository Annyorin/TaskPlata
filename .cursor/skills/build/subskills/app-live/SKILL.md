# App Live — screens + wire

## Среда

Код: `05-code/` или путь app-репо из `code-manifest`.  
Входы: `ds-manifest`, `04-prototype/outputs/build-log.md` + SCREEN-MAP / сценарии.

Предусловие: `ds-to-code` пройден (есть база) **или** пользователь указал существующий
репо с компонентами.

## Goal

Переносится **поведение**, не картинка. Экран из своих компонентов; каждый контрол
отвечает; edge-cases пережиты.

## Process

### A. Карта соответствий (`proto-map` в NOTES или `05-code/outputs/proto-map.md`)

| Figma / экран | Код | Статус |
|---------------|-----|--------|
| Button | components/Button.tsx | есть / создать / дрейф |

Дивы вместо существующих компонентов запрещены.

### B. Screens (по одному экрану основного флоу)

1. Структура из Figma / screen-spec — через MCP точечно.
2. Сборка **только** из базы + layout.
3. Тексты — ключи content-package, если есть; иначе временные моки с пометкой.
4. Данные — `src/data/*`, не строки в JSX.

### C. Wire (поведение сразу)

На каждый интерактив:
- переход / изменение на месте / тост;
- навигация с анимацией (резкая подмена = баг);
- формы: controlled/uncontrolled + ошибка валидации видима.

Правила wire:
1. Вид контрола = обещание действия.
2. У действия есть видимый результат.
3. Необратимое — с подтверждением.
4. Один флоу — один хост.
5. После тапа: «я понял, что произошло?» — молчание = дефект.

### D. Edge-cases (таблица обязательна)

| Экран | empty | error | long text | extreme data | double-tap |
|-------|-------|-------|-----------|--------------|------------|
| | ok/fix | | | | |

Чини сразу; покажи таблицу пользователю.

## Gate

- [ ] proto-map актуален;
- [ ] happy-path основного сценария проходим кликами;
- [ ] edge-таблица заполнена;
- [ ] code-manifest: экраны отмечены.

## Rules

- Не продакшен-backend: моки.
- Чужой командный репо — только своя ветка.
- Расхождение Figma↔код по виду — решение пользователя.
- Анимации UI — `emil-design-eng` при полировке.
