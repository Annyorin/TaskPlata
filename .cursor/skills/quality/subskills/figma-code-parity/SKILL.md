# Figma ↔ код: сверка компонента

Источник вида — узел в Figma. Код в `05-code/` — следствие. Компонент нельзя
называть готовым, пока эта сверка не записана.

Не путать с `design-review` (макет против системы) и с `user-test-loop`
(находки людей). Здесь сравниваются два артефакта одного компонента.

## Когда обязательно

Каждый раз, когда в `05-code/components/` или в его истории Storybook
появляется или меняется компонент. Правишь пачку — сверяешь каждый
затронутый компонент, не «самый заметный».

## Пара

В строке `05-code/outputs/code-manifest.md` у компонента должны быть:

- файл и история Storybook;
- fileKey и node-id узла-эталона;
- статус сверки: `match`, `brand-exception` или `diverge`.

Нет node-id — сверка не начинается, компонент остаётся незакрытым.

Узел берётся из `02-design-system/outputs/ds-manifest.md`, если это
компонент Plata. Системный хром iOS, которого нет в манифесте DS,
сверяется с тем узлом, который назвал пользователь. Ключ из чужой
библиотеки, который не вставляется в файл Payments, не считается
эталоном: в отчёте пишется «копия по скриншоту», статус не выше `diverge`.

## Замер

1. `create_session` на файл эталона.
2. С узла снять: ширину и высоту, радиус, заливку, обводку, шрифт
   (семейство, размер, вес, интерлинию), иконку, отступы, варианты.
   Эффект `GLASS` и режимы наложения записать отдельно. Не подменять
   их словами «полупрозрачный».
3. Скриншот узла (`get_screenshot`).
4. Открыть историю Storybook этого компонента и снять скриншот.
5. Сличить по списку ниже. Цвета в коде — только токены из
   `05-code/tokens/tokens.css`, кроме замера, который в токене ещё нет:
   тогда в отчёте назвать и hex из Figma, и отсутствие токена.

| Поле | Совпадает, если |
|------|-----------------|
| Размер | ±1 px |
| Радиус | то же значение |
| Заливка и текст | тот же токен или тот же hex |
| Шрифт | то же семейство, размер, вес |
| Иконка | тот же знак из пакета Plata или тот же SF Symbol |
| Варианты | те же, что у набора в Figma, лишних нет |
| Материал | стекло и тень из файла, не «похожая» заливка |

Оранжевый Plata вместо синего iOS допустим только как `brand-exception`
и только если пользователь просил сохранить бренд. В отчёте это пишется
явно. Остальные поля при этом всё равно сверяются.

## Статус

- `match` — все поля совпали.
- `brand-exception` — совпало всё, кроме согласованного акцента Plata.
- `diverge` — есть хотя бы одно другое поле, стекло заменено размытием,
  иконка нарисована заново или вариант пропущен.

`diverge` закрывает задачу только так: в ответе список расхождений
(поле, значение в Figma, значение в коде) и компонент не называется готовым.
Чинка — следующим шагом, если пользователь не остановил сверку.

## Куда писать

Одна строка на компонент в `05-code/outputs/parity.md`:

```
| Компонент | node | Story | статус | что разошлось | дата |
```

Файл завести при первой сверке, frontmatter: `type: parity`, `status`, `updated`.

## Gate

- [ ] У каждого затронутого компонента есть node-id.
- [ ] Есть кадр Figma и кадр Storybook.
- [ ] Статус записан в `parity.md` и в строку code-manifest.
- [ ] `diverge` назван в ответе пользователю.
