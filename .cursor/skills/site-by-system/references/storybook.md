# Storybook простыми словами и минимальный сетап

## Что это

Storybook это отдельная страница-витрина, которая живёт рядом с проектом и показывает каждый компонент сайта сам по себе: кнопку без страницы вокруг, карточку без соседей, шапку без контента под ней. У каждого компонента есть «истории»: его варианты и состояния. Открываешь витрину и видишь всю систему целиком.

Зачем это дизайнеру, который собирает сайт с агентом:
- Как выглядит элемент, решается один раз, в витрине. Страницы только используют.
- Правка компонента в витрине расходится по всем страницам.
- Видно, чего в системе нет: если для секции нужен компонент, которого нет в витрине, это заметно сразу.
- Агент, которому сказано «работай по Storybook», перестаёт выдумывать стили на каждой странице.

## Сетап (React + Vite)

```
npm create vite@latest <проект> -- --template react
cd <проект>
npm install
CI=1 npx storybook@latest init --yes --no-dev
```

Флаги обязательны: без них установщик задаёт вопросы и сам запускает сервер. Установка тянет много пакетов и идёт 10–15 минут, запускай её в фоне и в это время разбирай референс. Витрина потом открывается командой `npm run storybook` на localhost:6006.

После установки:
- удалить `src/stories/` с примерами: там хардкод цветов;
- дождаться конца установки и только потом писать `.storybook/preview.jsx` (иначе установщик его перезапишет): импорт `../src/tokens.css` и фон канваса из токена `--bg`, чтобы витрина показывала компоненты на их родном фоне;
- шрифт: `npm i @fontsource-variable/<имя>` (или ссылка Google Fonts в `index.html` и в `preview.jsx`);
- иконки: `npm i lucide-react`.

## Как устроена история

Один файл на компонент, рядом с ним: `Button.stories.jsx`.

```jsx
import { Button } from './Button'

export default { title: 'Primitives/Button', component: Button }

export const Primary = { args: { children: 'Забрать первый урок' } }
export const Secondary = { args: { children: 'Подробнее', variant: 'secondary' } }
export const Disabled = { args: { children: 'Недоступно', disabled: true } }
export const LongLabel = { args: { children: 'Очень длинная подпись, которая проверяет перенос' } }
```

Правило: у каждого компонента истории на варианты и состояния, которые задаются пропсами, включая неудобные: длинный текст, пустое значение, ошибка. Наведение и нажатие описываются в CSS компонента, историй под них не нужно. Если состояние не показано в витрине, его нет в системе.

## Структура витрины

```
Foundations/   токены: цвета, шрифты, отступы (показать таблицей)
Layout/        Stack, Grid
Primitives/    Text, Button, Tag, Card, Input, Divider
Organisms/     Nav, Footer, Section, SectionHead, Hero, CTA, дальше FeatureList, Reviews, FAQ по потребности
Pages/         собранные страницы целиком (для проверки, не для правки стилей)
```

## Что запрещено в компонентах

- Значения цветов и размеров цифрами: только `var(--token)`.
- Стили, которые зависят от конкретной страницы.
- Второй акцентный цвет.
- Эмодзи вместо иконок.
