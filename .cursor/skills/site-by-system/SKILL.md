# site-by-system

Скилл учит агента одному порядку работы: **сначала система, потом страницы.** Система живёт в Storybook: это каталог, где каждый компонент сайта показан отдельно, во всех своих вариантах и состояниях. Страница собирается из компонентов каталога и ничего не выдумывает на месте. Так результат получается консистентным и аккуратным, а не «каждый раз заново».

## Главное правило

Ни одна страница не верстается с нуля. Порядок всегда такой:

1. Референс → разбор → токены и правила (DESIGN.md).
2. Токены → компоненты в Storybook, каждый с историями.
3. Страница → только из компонентов каталога.
4. Не хватило компонента → сначала он появляется в Storybook, потом на странице. Никаких локальных стилей «только для этой секции».

Если пользователь просит «просто сверстай лендинг», всё равно иди по шагам. Объясни одной фразой, почему: без системы каждая новая страница будет выглядеть иначе, а правка в одном месте не разойдётся по остальным.

## Шаг 0. Знакомство: что будем делать и что нужно

При первом запуске объясни пользователю коротко, своими словами:

- **Что такое Storybook.** Отдельная страница-витрина рядом с проектом, где каждый элемент сайта (кнопка, карточка, шапка, секция) показан сам по себе, во всех вариантах: обычная кнопка, кнопка при наведении, кнопка выключенная. Это единственный источник правды: как выглядит кнопка, решается один раз здесь, а не на каждой странице.
- **Почему работаем по нему.** Страницы собираются из готовых проверенных кусков, поэтому они одинаковые по стилю, правятся в одном месте, и ты видишь всю систему целиком, а не только одну страницу.
- **Что нужно от пользователя.** Референс: ссылка на сайт или несколько скриншотов сайта, который ему нравится. Достаточно одного, но чем больше экранов, тем точнее разбор. И папка проекта: пустая или существующая.

Спроси ровно две вещи: референс и куда ставить проект. Стек не спрашивай, по умолчанию React + Vite + Storybook, ставишь сам. Если у пользователя уже есть проект на другом стеке, подстраивайся под него.

Если пользователь сказал «делай всё подряд, не спрашивай», остановки «дождись ок» ниже пропускай и показывай результат в конце каждого шага одной строкой.

Сразу после ответов создай проект, чтобы было куда класть файлы (команды в `references/storybook.md`, раздел «Сетап»): установка Storybook тянет много пакетов и идёт 10–15 минут, запусти её в фоне и пока разбирай референс.

## Шаг 1. Разбор референса

Сначала сними референс, по ссылке на глаз ничего не разбирай. Как снимать, написано в `references/decompose.md`, раздел «Как снять референс»: скриншоты всей страницы на 1440 и 390, вычисленные стили заголовков, текста и кнопок, переменные и подключённые шрифты. Потом разложи по шести осям. Разбираем **механику**, не копируем картинку: не «синий фон», а «тёмная поверхность, один тёплый акцент, свет идёт сверху».

Результат шага: файл `DESIGN.md` в корне проекта (правила словами, 8–12 пунктов) и `src/tokens.css` (цвета, шрифт и шкала, отступы, радиусы, тени). Покажи пользователю оба файла и один абзац: что делает этот стиль узнаваемым. Дождись «ок» перед следующим шагом.

## Шаг 2. Система в Storybook

Читай `references/storybook.md` (минимальный сетап и как устроена история). Собирай снизу вверх:

0. **Foundations:** первая история в витрине это таблица токенов: цвета, шрифт и шкала, отступы, радиусы. Она нужна, чтобы систему было видно целиком.
1. **Раскладка:** Stack (вертикальный ряд с отступом из шкалы) и Grid (колонки). Без них на странице появятся локальные стили, как только понадобится поставить два блока рядом.
2. **Примитивы:** Text (роли заголовков и текста), Button (варианты и состояния), Tag, Card (в том числе вариант под визуал: соотношение сторон и плейсхолдер), Input, Divider.
3. **Организмы под первую страницу:** Nav, Footer, Section (обёртка с отступами), SectionHead (заголовок секции), Hero, CTA-блок. FeatureList, Reviews и FAQ добавляй, когда они нужны странице. Reviews собирается только на плейсхолдерах: отзывы не выдумываются.
4. **Иконки:** один набор (Lucide, `npm i lucide-react`), один размер в тексте, один самостоятельный. Эмодзи вместо иконок запрещены.

Минимальный набор под лендинг: Foundations, Stack, Text, Button, Card, Section, SectionHead, Hero, CTA, Nav, Footer. Остальное по потребности страницы, не заранее.

Правила сборки:
- Значения только из токенов. Хардкод цветов и размеров в компонентах запрещён. Три исключения, других нет: ширина брейкпоинта в media query (переменные там не работают), хэйрлайн 1px, смещение фокусной рамки.
- У каждого компонента истории на варианты и состояния, которые задаются пропсами: обычное, выключено, загрузка, пустое, ошибка, длинный текст. Наведение и нажатие живут в CSS компонента, отдельная история под них не нужна.
- Один акцент. Он может быть не цветом, а приёмом: инвертированная кнопка, единственная плоскость другого тона. Цвета статусов (успех, предупреждение, ошибка) акцентом не считаются.
- Шрифты: те, что в DESIGN.md, подключены реально (пакет `@fontsource/<имя>` или ссылка на Google Fonts в index.html), не «похожие».
- Примеры, которые Storybook создаёт при установке (`src/stories/`), удаляются сразу: там хардкод цветов, и они засоряют витрину.
- Фон канваса витрины ставится из токена `--bg`, иначе тёмные компоненты на белом канвасе выглядят сломанными.

Результат шага: Storybook запускается, в нём все компоненты, у каждого истории. Покажи пользователю каталог одним экраном и остановись.

## Шаг 3. Страница из компонентов

Сначала бриф страницы в трёх строках: кто её читает, что должен понять, что нажать. Потом скелет: список секций сверху вниз, для каждой какой компонент. Покажи скелет, дождись «ок».

Собирай страницу **только** из компонентов Storybook. Проверка на каждой секции: есть ли в ней хоть один стиль, которого нет в системе? Если да, это сигнал: компонент идёт в Storybook с историей, страница ждёт.

Контент: реальные тексты пользователя. Чего нет, ставь плейсхолдер с видимой пометкой «заменить» и веди список замен. Цены, цифры, отзывы, имена не выдумывать никогда. Визуалы (скриншоты продукта, фото) тоже не выдумывать: под них ставится Card с нужным соотношением сторон и подписью, что сюда вставить.

## Шаг 4. Проверка

Читай `references/checklist.md`. Сними экран на ширине 1440 и 390 (команды в чек-листе), пройди чек-лист, исправь одним заходом, пересними. Два круга максимум. Отдай пользователю: адрес страницы, адрес Storybook, список замен.

## Не делать

- Не верстать страницу до того, как в Storybook есть компоненты.
- Не добавлять стиль «только для этой страницы».
- Не копировать референс попиксельно и не тащить его тексты и картинки: берём механику стиля, не сам сайт.
- Не сваливаться в нейросетевой дефолт: индиго-фиолетовые градиенты, всё в одинаковых карточках по центру, эмодзи вместо иконок, системный шрифт вместо выбранного, ярлык-подпись над каждым заголовком, номера секций 01/02/03.
- Не выдумывать контент и цифры.
