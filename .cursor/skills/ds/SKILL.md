# DS — роутер группы

Среда: `02-design-system/`, строгая изоляция. Задача выполняется целиком внутри среды,
наружу уходит только `outputs/ds-manifest.md`.

Подскиллы лежат в `subskills/<имя>/SKILL.md` — прочитай нужный и работай по нему.

## Перед любой задачей создания / подключения DS

**Обязательный gate.** Если пользователь ещё не ответил в этой сессии — остановись
и спроси одним блоком (не начинай Variables, индекс или MCP-запись):

```
1. Готовая дизайн-система уже есть в Figma?
   → да: пришлите ссылку (fileKey) — индексируем / синкаем
   → нет: создаём с нуля
2. Если «с нуля»: pre-DS в среде 04 уже пройден
   (FigJam sitemap+flows → сценарии → low-fi wireframes + component inventory)?
   → да / пропустить pre-DS явно / ещё нет
```

| Ответ | Действие |
|-------|----------|
| DS есть + ссылка | `figma-ds-link` (разово) или `design-system-sync` |
| С нуля + pre-DS готов / skip | `handoff-to-figma` или foundations по брифу |
| С нуля, pre-DS нет | **Стоп.** Новая задача в `04-prototype/` / группа `structure`. Чеклист: `_shared/structure/PRE-DS-PIPELINE.md`. В этой задаче DS-файлы не трогать. |

FigJam, сценарии и low-fi **не делаются внутри среды 2**.

| Задача | Подскилл |
|--------|----------|
| разобрать визуальный стиль по референсу в `STYLE_GUIDE` | `style-decompose` |
| DS **нет**, есть бандл Claude Design — собрать её в новом файле Figma | `handoff-to-figma` |
| DS **уже есть** — разово проиндексировать в папку `ds/` | `figma-ds-link` |
| связать DS с кодовой базой надолго: токены, Code Connect, дрифт | `design-system-sync` |

## Выбор по направлению

| Направление | Подскилл |
|-------------|----------|
| референс → правила | `style-decompose` |
| код или бандл → Figma | `handoff-to-figma` |
| Figma → локальный индекс | `figma-ds-link` |
| Figma ↔ код, постоянно | `design-system-sync` |

Как именно ходить в Figma — не здесь, а в `infra/figma-mcp`: OAuth, разбор ссылок,
лимиты, последовательности вызовов. Все подскиллы группы — надстройки над ним.

## Объёмная задача — изолированная сессия

Среда 2 объёмная: полный обход не помещается в один контекст. Для синка целого
Figma-файла, массового обновления компонентов или аудита foundations — **вынеси в
субагент**, не отдельный скилл:

1. Запусти `Task` (`generalPurpose`) с границей «только `02-design-system/`».
2. В промпт: абсолютный путь среды, конкретные fileKey/node-id из `figma/registry.md`,
   обновление `figma/registry.md` + `figma/sync-log.md`, в конце — `outputs/ds-manifest.md`.
3. Ответ субагента ≤20 строк: изменено / дрейф / не сделано.
4. Параллель — только на непересекающихся наборах файлов.
5. После сводки проверь sync-log и манифест, не читая всю среду.

Точечная задача на один компонент — без субагента.

## Дедуп-вахта

- `figma-ds-link` и `design-system-sync` пересекаются на инвентаризации. Канон
  инвентаризации — `figma-ds-link`; `design-system-sync` зовёт его.
- Реализация компонентов в коде — среда `05-code` и группа `build`.
- `ds-to-storybook` — группа `build`: библиотека из бандла, не описание системы.
- Pre-DS (FigJam, сценарии, low-fi) — группа `structure`, не `ds`.
