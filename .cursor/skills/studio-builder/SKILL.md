# Studio Builder

Делает **инструмент, который делает картинки**. На выходе локальный веб-борд под конкретную повторяющуюся задачу: генерация вариантов, отбор, редактируемые слои поверх и экспорт в нужных форматах.

## Когда применять

Задача подходит, если она отвечает «да» на три вопроса:

1. Это повторяется. Каждую неделю, каждый запуск, на каждый товар.
2. Результат состоит из двух частей: картинка-образ и то, что должно читаться (текст, логотип, цифры).
3. Вариантов нужно несколько, и из них надо выбирать.

Обложки роликов, рекламные креативы, карточки маркетплейса, посты в соцсети, баннеры под кампании, превью курсов. Если задача разовая, интерфейс не нужен: генерируй напрямую.

## Главное правило, из которого растёт всё остальное

**Генерируется только образ. Всё, что должно читаться, кладётся слоем поверх.**

Причина техническая: генеративные модели кодируют картинку со сжатием, и мелкая графика при этом гибнет. Читаемый текст выходит примерно в пяти процентах генераций, кириллица ломается почти всегда, логотип искажается. Спорить с этим бесполезно, поэтому мы просто не просим модель рисовать текст.

Отсюда конструкция любой студии: снизу сгенерированный образ, сверху редактируемые слои, между ними отбор.

## Шаг 1. Разложить задачу

Не начинай собирать, пока не получишь ответы. Задай одним сообщением:

1. Что ты делаешь руками сейчас и как часто?
2. Что на выходе: формат, размеры, сколько штук за раз?
3. Что в этом всегда генерируется (фон, персонаж, предмет, сцена)?
4. Что в этом всегда должно читаться (заголовок, логотип, цена, теги)?
5. По какому признаку ты выбираешь лучший вариант?
6. Куда результат уходит дальше и под каким именем его там ждут?

Ответ на третий и четвёртый вопрос это граница между слоями. Ответ на шестой определяет экспорт, и его почти всегда забывают: если файлы называются как попало, через две недели непонятно, какой из них сработал.

Разложи задачу письменно и покажи пользователю до сборки:

```
Генерируем:   <что именно, какой моделью>
Кладём слоем: <что именно, каким шрифтом, где>
Отбор:        <сколько вариантов, по какому признаку>
Экспорт:      <форматы, размеры, схема имён>
```

## Шаг 2. Подключить генерацию

Higgsfield даёт около тридцати моделей изображений и видео через один эндпоинт.

Хостовый MCP, самый простой путь:

```
claude mcp add --transport http higgsfield https://mcp.higgsfield.ai/mcp
```

Дальше авторизация в браузере. Проверь, что работает: попроси агента показать баланс и список моделей.

Альтернатива, если нужен доступ из кода студии:

```
npm i -g @higgsfield/cli
higgsfield auth login
```

**Что надо знать до подключения:**

- На бесплатном тарифе MCP недоступен, он начинается с младшего платного.
- Безлимитные модели работают только на сайте. Любая генерация через MCP или CLI списывает кредиты, независимо от безлимита. Это заявленное поведение, так и задумано.
- Модели различаются по цене в разы: у одной картинка стоит один кредит, у другой шесть с половиной. Черновой перебор ведётся на дешёвой, дорогая включается после утверждения направления.

Если платить не готов, студия всё равно собирается и работает на уже готовых картинках: отбор, слои и экспорт от генерации не зависят.

## Шаг 3. Собрать интерфейс

Стек намеренно простой, чтобы человек мог его читать и править:

```
studio/
  server.py (или server.mjs)   локальный сервер, порт свободный
  public/
    index.html                 борд и редактор
    style.css                  стили
    fonts/                     шрифты проекта, обязательно локально
  assets/                      сгенерированные образы
  export/                      готовые файлы
  queue.jsonl                  очередь заявок на генерацию
  state.json                   текущее состояние отбора
```

Обязательные части борда:

- **Сетка вариантов.** Все заготовки видно одновременно, у каждой статус: черновик, в пуле, готово.
- **Редактор одной карточки.** Слева макет, справа панель: выбор образа, текстовые поля, композиционная схема, акцентный цвет.
- **Слои поверх.** Текст кладётся шрифтом проекта, подключённым локально. Размер подбирается автоматически под ширину кадра, чтобы не двигать вручную. Предусмотри подложку под текст на случай светлого образа.
- **Отбор.** Кнопка «в пул и дальше», чтобы проходить варианты потоком без возврата к сетке.
- **Экспорт.** Все форматы сразу, имена по схеме из шестого вопроса.

Шрифты обязательно локальные файлы в проекте. Если подключать их из сети, борд сломается без интернета и на чужой машине.

## Шаг 4. Очередь вместо прямого вызова

Интерфейс **не ходит в нейросеть сам**. Он пишет заявку в очередь, исполняет её агент.

```
  интерфейс  →  queue.jsonl  →  агент  →  assets/  →  интерфейс подхватывает
```

Почему так:

- в вебе не хранятся ключи и токены;
- агент может поправить промпт по ходу, а кнопка не может;
- прогон переживает закрытие вкладки;
- видно, за что списаны кредиты.

В интерфейсе покажи статус заявки, чтобы человек понимал, что происходит, и не жал кнопку второй раз.

## Шаг 5. Правила прогонов

Заложи их в интерфейс, чтобы человеку не приходилось держать их в голове:

- **Батчи параллельно.** Десять картинок очередью это двадцать пять минут, параллельно около трёх. Задачи независимы.
- **Черновики дешёвой моделью и в низком разрешении.** Финальное качество после утверждения направления.
- **Промпт всегда без текста.** В образ добавляется указание не рисовать надписи и буквы. Негативные промпты часть моделей не принимает, поэтому надёжнее сразу просить пустую композицию с местом под будущий текст.
- **Прерванный прогон не потерян.** Задача живёт на сервере, результат забирается позже.

## Шаг 6. Показать и передать

Подними сервер, открой борд, пройди один цикл целиком: заявка, приход вариантов, отбор, текст, экспорт. Покажи получившийся файл и объясни, где что лежит и как поменять.

## Чек-лист

- [ ] Задача разложена письменно на генерируемое и накладываемое, пользователь это подтвердил
- [ ] Генерация подключена и проверена, лимиты проговорены
- [ ] Борд открывается по локальному адресу, шрифты лежат в проекте
- [ ] Текст никогда не уходит в промпт
- [ ] Есть отбор потоком и экспорт с осмысленными именами
- [ ] Заявки идут через очередь, статус виден
- [ ] Один полный цикл пройден вживую

## Не делать

- Не просить модель нарисовать текст, логотип или интерфейс. Это не вопрос промпта.
- Не собирать универсальный редактор на все случаи. Студия делается под одну задачу. Вторая задача это вторая студия или вторая вкладка.
- Не подключать генерацию напрямую из браузера.
- Не оставлять экспорт без схемы имён.
